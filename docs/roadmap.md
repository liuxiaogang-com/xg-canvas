# XG Canvas Roadmap

> 本文只记录当前产品状态和后续方向，不承诺具体发布日期。最后复核：2026-07-16。

## 当前定位

XG Canvas 是面向企业创意团队的开源、自托管 AI 创意生产平台。当前目标不是补齐所有
登录渠道，而是先让团队能用简单账户体系进入系统，并稳定跑通“模型配置 → 生成任务 →
资产归档 → 调用与成本留痕”的核心链路。

## 已具备的基础

- 模块化单体：`canvas-web` + `canvas-api`。
- 项目、画布、节点、连线、快照、任务和资产的主要数据结构。
- 版本化 Model Catalog：Revision 唯一结构真相、三张 Runtime Settings、确定性 Bundle、严格
  Param/Input Contract、显式 Adapter/Channel 兼容图、任务/费率固定与单进程原子热切换。
- PostgreSQL、Redis 与远程 S3/R2 兼容对象存储接缝。
- 本地账户、会话、邮箱验证基础设施，以及系统级和项目级 RBAC。
- 预签名素材直传、可见性、收藏，以及人物 / 音色 / 风格资源库基础。
- 逻辑调用/物理 attempt 请求账本、未知分发 at-most-once 恢复、原生币种用量与历史成本记录基础。
- 脚本、角色、场景、道具、实体、分镜与表格视图的产品骨架。

以上能力均处于整体 Beta 中；“已有实现”不等于已经完成生产环境验证。

## 公开 Beta 前

- [x] 完成简洁可靠的注册、密码登录、退出、会话续期和管理员初始化流程。
- [ ] 打通至少两个主流服务商的真实图像/视频生成链路，优先百炼 / DashScope，并按真实验证结果扩展 Dreamina 等路径。
- [ ] 验证凭证配置、模型启用、任务执行、失败重试、资产转存和请求日志的端到端流程。
- [x] 完成用户素材与参考图上传，支持预签名直传并回写资产元数据。
- [ ] 校验 CNB 镜像在全新 PostgreSQL 数据卷上的冷启动、安装步骤、环境变量和 Catalog 导入流程。
- [x] 建立基础 CI 配置：类型检查、测试、lint、文件行数、Compose 校验与双镜像构建发布。
- [ ] 补齐安装、Provider 配置、首个工作流和故障排查文档。

手机号验证码、微信生态登录、飞书和企业微信登录不作为公开 Beta 的前置条件。它们应在
核心生成链路稳定后按真实客户接入需求逐步实现，避免认证渠道挤占产品验证资源。

## 团队可用性

- [ ] 工作流模板、版本、发布、权限和团队复用。
- [ ] 人物 / 音色 / 风格资源的版本管理、厂商绑定验证和跨项目复用体验。
- [ ] 项目/成员/模型预算，余额提醒、软限制与硬限制。
- [ ] 基于价格、能力、速率与凭证健康度的模型路由。
- [ ] WebSocket 任务进度推送与更完整的失败诊断。
- [ ] 预设命令快速插入，以及 Word、Excel、Markdown 剧本导入。
- [ ] Agent 工具调用循环、任务执行和结果回填画布。
- [ ] 自定义角色与更完整的审计查询界面。
- [ ] 标准化 Node / Adapter 扩展包、示例工程与契约一致性测试。

## 企业集成与规模化

- [ ] OIDC、SAML、LDAP、SCIM，以及飞书和企业微信等组织身份接入。
- [ ] 多 Workspace、多租户、实时协作、评论与审核流。
- [ ] Vault/KMS 等外部密钥系统，审计导出与 SIEM 集成。
- [ ] 独立 Worker、分布式队列、高可用、备份恢复与可观测性。
- [ ] 企业内部节点、Provider、数据源和业务系统集成模板。

## 当前已知技术债

- 真实厂商与生产部署的端到端覆盖仍不足。
- 远端 Catalog 分发、签名、更新审批和调度尚未实现。
- 多 API 副本间的 Catalog 变更通知与一致性屏障尚未实现；当前热切换保证单进程原子性。
- Catalog-native 全新数据库冷启动与基线重建说明仍需生产环境验证；本 Beta 基线不接收此前数据库。
- 测试覆盖集中在约束引擎、Adapter 请求构建和任务状态机，前端与集成测试需要补齐。
- 部分规格与现有接口仍需持续对账，以代码行为和对应权威 spec 同步更新。
- Agent、实时协作、预算限制和企业 SSO 仍属于后续能力，不能作为当前可用功能宣传。
- **开源首发暂隐能力清单**（加节点菜单、衍生工具条、`@` 提及、详情弹层等）见
  [open-source-deferred.md](./open-source-deferred.md)；代码保留、UI 门禁，恢复时勾选该清单。

## 优先级原则

1. 真实生成链路优先于增加大量登录方式。
2. 凭证隔离、任务可靠性、资产归属和成本留痕优先于继续堆叠节点数量。
3. 先用一个可部署版本验证企业工作流，再按客户需求扩展身份、审批和集成。
4. 公开文档只描述当前规范与真实状态；历史研究和阶段性执行清单不进入公开仓库。
